# Todo 清单

侧栏「待办」提供独立于终端与协作组的清单。待办可以手动添加、由外部程序注入，或由多个自定义收集 Agent 写入。数据保存于服务所在用户的 `~/.termdock/todos.json`，包含收集方向、执行默认值和每轮终端/结果记录。

手机或桌面侧栏收起时，终端顶部右侧以轻量文字显示「待办＋未完成数量」，不使用独立灰色卡片或重复图标，不需要先打开会话侧栏；会话标签横向滚动时，该入口仍留在顶部。待办页左上角「终端」直接回到当前终端，重新进入时保留筛选、选择与页面会话中的草稿。桌面侧栏固定展开时只显示侧栏入口，隐藏顶部入口，避免重复。

## 使用

- 清单默认直接显示未完成事项；顶部「＋」新增、「收集」启动已启用的收集方向。搜索、状态与来源筛选、多选、已完成、已忽略、收集方向、执行设置和外部接入都在「更多」菜单中，按需展开。
- 新增待办填写标题与背景，可「仅保存」或「保存并处理」。清单圆圈直接标记完成；详情在确认完成后返回清单，并短暂提供「撤销」。多选只处理尚未发起或启动失败的事项，避免重复启动已有任务。
- 详情直接展示报告与当前主要操作：交给 Agent、查看执行、确认完成或重新处理。原始待办、配置与历史默认折叠；编辑、重新发起、忽略等操作收进任务菜单。收到报告后仍需用户确认完成，不根据终端活动推断工作进度。
- 启动命令与「开始新会话」共用当前浏览器的 Agent 命令方案。每个 Agent 可命名保存多套命令、快速切换、编辑或删除；新建方向与首次配置沿用最近选择。已有方向、执行默认值及历史任务保留所保存的命令，需在配置中主动切换并保存才更新。旧版命令自动保留，独立 Shell 自定义命令不受影响。
- 首次执行按需配置 Agent 与目录；已有执行默认值时直接启动，否则可复用最近保存的收集配置并记为执行默认值。首次配置默认采用用户的新会话 Agent 偏好。最近选择按服务保存在浏览器中，刷新后可用，不把收集提示词带入执行或下一方向。
- 工作目录提供「当前会话」和最近项目快捷按钮，包含会话、收集方向与任务历史中的目录。收集生成的待办默认沿用该方向目录；批量处理不同项目时分别保留目录，重试保持原配置与请求标识。任务菜单允许单次调整配置。
- 首次点击「收集」进入方向配置；「保存并收集」立即启动并返回清单。后续从清单一次启动全部启用方向，各自使用独立 Agent 终端，待办自动写入清单。通过菜单进入「收集方向」管理提示词、Agent、目录、启用状态及计划；长报告与历史收进「收集记录」。可选手动、间隔或每日计划，使用服务所在时区，调度不依赖页面在线。
- 每条待办对应独立执行终端。运行机器是当前连接的服务，换机器需先切换服务。输入已写入终端仅表示投递；启动失败可排查已有终端或重试，服务重启不会重放尚未确认的启动。忽略的条目可从「已忽略」重新打开。
- 切换手机/桌面布局、打开 Agent 终端再返回，会保留当前筛选、详情和页面会话中的草稿；关闭表单再打开也可继续填写。页面刷新后不保证保留未提交草稿。已保存的执行默认值与收集方向在服务端持久化。

收集与执行采用系统已安装的 Agent CLI，继承各自的登录、工作区信任和权限配置。首次启动出现 Agent 自身的授权问题时，在「打开终端」处理。应用不接管各家 Agent 的模型循环。

## 外部写入

在服务所在机器、同一系统用户下：

```sh
td todo add --title '检查项目依赖' \
  --description '核实升级影响，整理处理建议' \
  --source '项目巡检' --external-id 'deps-review'
td todo list
td todo complete <todo-id>
td todo reopen <todo-id>
td todo ignore <todo-id>
```

`--description` 可换为 `--file <UTF-8 文件>` 或 `--stdin`；来源链接用 `--url https://...`。
同一 `source + externalId` 返回已有记录，不覆盖用户编辑、完成状态或重新打开条目。`--idempotency-key` 用于请求重试；同一 key 携带不同内容返回冲突。不同方向相似内容不会自动合并。
收集 Agent 还可附 `--collector <collector-id>`，应用会在收集任务的提示词中附上正确用法。删除方向后已经启动的收集 Agent 仍可完成写入，原待办与历史保留。

每轮执行的提示词附带对应 run ID。提交结果：

```sh
td todo report <run-id> --status complete --file /path/to/result.txt
# status 还可以是 blocked 或 failed；不会自动完成 Todo
```

报告绑定具体 run，迟到的旧结果不会覆盖新一轮。一个 run 的报告重复提交相同内容可重试；不同内容须新开一轮。`td todo --help` 不依赖运行中的服务。

## HTTP 接口

统一前缀 `/api/terminal/operations/todos`。继承现有终端 API 的认证、CSRF、服务授权和加密传输规则；浏览器通过页面加密 fetch 使用。本机 CLI 使用 loopback 与私有本机 token。没有匿名写入或业务 HTTP 降级。

| 方法与路径 | 内容 |
| --- | --- |
| `GET /` | todos、collectors、runs、defaults |
| `GET /summary` | 未完成数量 |
| `POST /` | title、description、source、sourceUrl、externalId、collectorId、idempotencyKey |
| `POST /:id` | revision 与 title / description / status（open、completed、ignored） |
| `POST /:id/run` | config 与 idempotencyKey；返回已保存的启动记录 |
| `POST /defaults` | agentSlug、command、cwd、prompt |
| `POST /collectors` | name、config、enabled、schedule；编辑时加 id 与 revision |
| `POST /collectors/:id/run` | idempotencyKey |
| `POST /collectors/:id/remove` | revision |
| `POST /runs/:id/report` | status（complete、blocked、failed）、content |

启动与注入带稳定请求标识，记录先持久化再创建终端。网络断开后应使用原 key 重试，避免重复创建。日常 UI 的批量启动会分别保留成功与失败项，可重试失败项。首版不提供跨服务汇总、内置来源抓取或自动验收。
