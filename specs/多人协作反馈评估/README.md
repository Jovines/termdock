## 1.4.235 自动登记补充

- 正常连接已授权服务时，新页面读取已保存的服务目录，通过固定服务身份的加密连接取得公开描述，再向各自已授权服务登记；无需额外执行配对 CLI。
- 每端必须已有持久管理授权。旧 macOS 客户端按服务保存不同设备身份时，两端各加载一次新页面，由各自授权连接完成登记；不复制设备私钥，也不绕过授权。
- 登记完成后目录发现、群同步、消息和回执均由服务端维护，客户端不承担协作转发。旧 preload 只提供本机保存的服务连接元数据。
- 离线或尚未升级的服务稍后重试登记；“重试跨服务连接”也会触发登记。地址、身份与证书冲突明确拒绝。
- 按用户要求跳过回归测试；执行生产构建和部署健康检查。真实 macOS 双端自动登记尚未验收。

## 1.4.236 单向网络上的双向协作

- 复现：协调者服务能主动访问维护者服务，反向网络不可达；此前只允许请求方发起业务，维护者误把协调者的 localhost 当作拨号地址。
- 增加服务端双向 RPC：已登记服务通过 Noise 身份验证并申请复用连接后，双方都可在同一条连接上发起目录、群同步和消息/回执请求。反向请求仍逐条执行原有服务及群权限检查，不开放通用 HTTP 或终端控制。
- 收到的连接按服务 ID 登记，目录与消息发送优先复用；关闭时移除并拒绝未完成请求，由原有后台周期重新连接。新连接到达立即唤醒消息重试。
- 对方描述中的 localhost 保留作现有群成员标识，不再用它拨号；由该服务主动建立出站连接。已有群和待发消息无需重新创建。
- 双方 CLI 服务均需更新才能启用双向 RPC。旧服务允许原有出站请求，但不能解决单向网络中的反向投递。
- 按用户要求不跑回归测试；构建及本机部署检查不等同于真实 macOS 双端验收。

### 1.4.237 登记时序补丁

双向连接建立时若另一端尚未登记，关闭本次连接并由后台重试，避免保留只能单向请求的连接。显式 CLI 邀请配对使用独立的首次登记连接，配对完成后再建立双向连接。

## 1.4.238 协作界面的服务别名

- 侧栏成员与协作面板使用本机保存的服务别名，优先按服务 ID 匹配；不把别名写回远端或改动连接地址。
- 收件人默认只显示成员名，同名成员追加服务别名；无可用别名显示“远端服务”。地址和 URL 不再作为普通成员标签或悬停提示。
- 服务别名更新会刷新协作目录；侧栏持久化成员信息合并当前目录的名称和在线状态。
- 地址保留在服务连接配置及诊断数据中。按用户要求跳过回归测试，执行生产构建与部署检查。
- 全仓类型检查仍有既存 6 处错误：LeftSidebar 未使用的 RiAddLine；rightSidebarRepoGroupCollapse.test 的 deferred；useSidebarStore.test 三处 pinnedExplorerRoots；settings.test 返回类型。均不在本次修改的代码段中，未改动；本次新增代码未报类型错误。
