# 加密连接与 CLI 中继

## 统一连接内核

连接按“身份与地址 → 加密建连 → 中转通道 → 业务授权”处理。地址、可用通道和权限分别验证；列表中的可用通道表示当前存在候选提供者，最终目标仍在每次连接时验证 Noise 身份和业务权限。

| 公共模块 | 统一规则 | 使用入口 |
| --- | --- | --- |
| `connectionModel.ts` | 地址规范化、直连与入口分离、按“服务 ID + 地址”去重、旧记录合并后清除错误直连地址 | 页面、后台通知、原生连接目录适配、服务端目录发现 |
| `serviceTransport.ts` | TLS 信任模式、固定端点、超时与取消、握手前订阅 ready、失败清理 | CLI 中继、反向中继、直连提供者、身份探测、服务间 RPC |
| `relayTransport.ts` | ready/open/data/close 状态机、密文帧预算、授权失败、关闭后禁止发送 | 浏览器/PWA/Preview 页面、后台通知、服务间 RPC；浏览器 `RelaySocket` 只负责适配 |
| `connectionErrors.ts` / `connectionAttempts.ts` | 可区分的身份/授权错误、最多两个并行候选、30 秒整轮预算、取消和迟到连接清理 | 前台连接与后台通知；一次性邀请保持串行 |
| `directTargetRegistry.ts` / `relay.ts` | 每个地址独立验证与撤回、最多四个并发探测、提供者续期/失败切换、单通道取消传到目标建连 | 管理员固定路由、桌面服务目录、CLI/自动反向提供者 |

设备授权、CLI 的登记令牌、服务间协作授权各自保留权限边界。中转核心传递密文并检查路由使用权；目标服务检查查看、输入、文件及协作权限。通道建立后失败会关闭该通道，调用端重新验证身份后建连；终端输入与写入不会在提供者间自动重放。

同一服务的多个地址分别保留，某个地址失效或被删除不会移除其它地址及反向提供者。入口授权撤销作用于该入口身份的所有地址；前台可以尝试另一个已经保存的入口或独立直连，恢复过程不创建新授权，也不重新添加撤销的入口。目标确认设备授权失效时，停止整轮恢复并要求重新授权。

TLS 支持系统/进程默认信任、显式 CA 文件、固定 CA 指纹和 Preview 叶证书指纹。后三种模式独立且不能混用。支持系统 CA 枚举的 Node 版本会在未指定独立信任时采用进程默认与操作系统信任库；不修改进程全局 TLS 配置，固定指纹和 CA 文件仍只使用各自批准的信任。API 行为见 [Node TLS 文档](https://nodejs.org/docs/latest-v22.x/api/tls.html#tlsgetcacertificatestype)。

测试使用临时配置和真实 WSS + Noise，Mac 后台隔离测试与签名 App/iOS 真机验收分别记录。新增入口应复用以上内核，通过已有路径发送业务数据，并补充对应矩阵场景。

手机直连沿用原密码登录页。浏览器使用现有密码完成 OPAQUE 双向证明，验证服务身份并授权设备，再建立 Noise 加密连接；密码及现有 scrypt 凭据不会随请求发送。设备身份在浏览器 IndexedDB 中保存，密码授权有效期为 30 天，修改密码或退出登录会使相关授权失效。

无密码服务保留直接进入的行为：首次通过 HTTPS 获取并固定服务身份，随后建立 Noise 连接。此开放模式首次信任依赖 HTTPS，不具备密码证明的独立身份保证；启用密码立即终止开放权限，开放身份不能创建持久授权。

分享访问使用“服务与设备 → 邀请设备”，选择只读、可操作或整服务权限，生成十分钟有效、只能使用一次的链接和二维码。接收端打开链接后接受邀请，无需抄写服务 ID 或 JSON。服务端 CLI 的 `termdock --federation-pairing [--url https://service:9834]` 同样输出邀请链接和二维码，只有兼容旧工具时才使用 `--json`。CLI 配对码从本机 `~/.termdock/federation/pairing.json` 读取，通过可信方式分享。

下列配置是管理员启用跨服务路由的步骤，普通手机密码登录不需要配置它们。入口 B 配好 C 的路径后，在 B 的“添加服务”粘贴 C 的邀请链接；浏览器通过 B 请求通道，由 C 独立授权。

A 能访问 B、C，而 B、C 无法互通时，在 A 上运行：

```sh
chmod 600 relay.json
termdock --federation-relay relay.json
```

`relay.json` 示例（替换所有示例值）：

```json
{
  "entryUrl": "https://b.example",
  "relayToken": "replace-with-a-random-token-at-least-32-characters",
  "caPath": "trusted-ca.pem",
  "targets": [
    { "serviceId": "C-verified-service-identity", "url": "https://c.example", "caPath": "c-trusted-ca.pem" }
  ]
}
```

B 的 `~/.termdock/federation/routes.json` 配置对应 `{ "relays": [{ "id": "A", "token": "同一个随机令牌", "targets": ["C-verified-service-identity"] }] }`。配置文件含凭据，使用 `0600` 权限。中继令牌只允许登记和转发已列出的目标，不授予任何目标终端权限。

URL 仅接受 HTTPS/WSS，证书和主机名必须验证，不允许跳转。`caPath` 可省略以使用系统信任；设置时使用指定 CA，路径相对于配置文件，目标可单独覆盖 CA。禁止通过关闭证书校验绕过错误。

进程持续运行并在连接中断后退避重试。SIGINT/SIGTERM 关闭活动通道；A 休眠或退出时依赖它的访问失效。目标身份、配对和端到端加密在客户端与 C 之间完成，中继只传递加密载荷。

配对及授权 UI 支持整服务完整权限，或指定后端 Session 的查看、输入、尺寸和终止权限。输入权限可以执行该终端系统用户有权运行的命令。活动通道必须在目标持续检查授权，撤销后不可继续使用旧流。

普通 PWA 仍须信任代码来源。应用层加密不能阻止被替换的前端在加密前读取输入；不能把普通 PWA 宣传为可抵御主动替换前端代码的 HTTPS 代理。

运行时要求 Node.js 22 或更新版本。加密实现使用 `@chainsafe/libp2p-noise` 17.0.0 与 Ed25519 设备身份，密码证明使用 `@serenity-kit/opaque` 1.1.0。连接达到 60 分钟或任一方向 512 MiB 时关闭，重连重新握手；不重放未确认的终端输入。HTTP 上传按块背压，最大 110 MiB。服务端身份文件权限为 `0600`；浏览器密钥可被同源代码使用，不宣称硬件不可导出保护。

## 传输性能与兼容

权限响应同时声明 HTTP 传输能力，不增加独立的能力探测往返。新版客户端和服务端使用最多八个 64 KiB 分块的在途窗口，并直接在 Noise 内传输二进制文件分块，省去 Base64 的体积膨胀。服务端未声明能力或旧客户端未请求能力时，继续使用逐块确认和 JSON/Base64。上传进度只计算已确认字节；下载仅在消费数据后返回窗口额度，暂停消费、取消和断线都不会转为直连 HTTP。

批量文件发送在共享记录队列达到 512 KiB 或 128 条时等待释放事件，为终端输入、确认和取消保留容量；硬上限仍为 4 MiB / 256 条。逻辑连接的 `bufferedAmount` 返回尚未交给下层的本连接记录字节，不代表网卡积压或对端确认。

支持 gzip 解压的客户端会为终端订阅请求独立记录压缩。服务端在 Noise 加密前异步压缩至少 4 KiB 的输出，只有计入 Base64 和信封后仍节省至少 10% 才采用压缩；小消息直接发送，不保留跨消息字典。解压上限为 2 MiB，记录身份和类型必须与外层一致。公开 WebSocket 只承载密文，关闭其 `permessage-deflate`，避免压缩密文消耗 CPU。

`transfer.integration.test.ts` 使用真实 WSS + Noise，覆盖直连和只能经中转访问的目标、文件校验、窗口、终端消息与取消。在每帧独立注入 30ms 单向传播延迟（约 60ms RTT）的本机单样本测试中，1 MiB 上传由约 1.4–1.7s 降至约 0.4–0.5s，下载由约 1.4–1.8s 降至约 0.3–0.5s。此测试不模拟带宽、随机丢包或真实广域网，不代表所有用户的加速比例。

HTTPS 服务现在同时启动原生 UDP/HTTP3 WebTransport 监听器（默认与 TCP 同端口）。浏览器先在 WSS + Noise 上完成身份/权限验证，从加密权限响应获得短期 ECDSA 证书指纹，再后台建立 QUIC；每个终端使用独立的可靠 QUIC 流和独立 Noise 密钥/记录序列，HTTP 流可以顺序复用，最多八个并发请求。终端流设置较高的浏览器发送优先级。独立流减少丢包时跨流的交付阻塞，但仍共享拥塞控制和物理带宽，不能保证所有链路都加速。

已经建立的 TCP 终端在输入静默两秒且队列清空后通过输出游标重新挂接 QUIC，不重放输入；QUIC 建立后业务控制也有独立流，原 TCP 断开不影响已迁移终端。UDP 被阻断、浏览器不支持证书指纹模式或可选原生模块不可用时保留加密 WSS。只有尚未发送业务记录的新流握手失败可以回退；已发送的上传和输入失败直接上报，不能自动重发。只能通过入口中转的目标继续走既有端到端加密 WSS，中转本身尚未迁移到 QUIC。

部署时放行对应 **UDP** 端口，HTTP 反向代理仅转发 TCP 不会自动代理 QUIC。`TERMDOCK_QUIC=0` 可关闭；`TERMDOCK_QUIC_PORT` 可设置监听端口（同时作为客户端连接端口，NAT 必须保持此端口映射）。浏览器连接地址继承已认证 WSS 的主机，证书指纹不接受任意目标地址。QUIC 证书自动生成并以 `0600` 保存到 federation 目录，十三天有效，提前轮换；HTTPS CA 和客户端固定的 Noise 身份保持原有配置。已有会话的证书不因轮换而变化，下一次权限响应发布新的指纹。

`webTransport.integration.test.ts` 使用真实 QUIC 原生模块、WSS 和 Noise，覆盖终端独立于暂停下载、并发上传下载 SHA-256 校验、HTTP 流复用、失去 TCP 后继续输入、UDP 失败回退，以及已发送写入失败不重发。真实 macOS/iOS 的弱网、换网、原生桥接与后台通知仍须实机验收；桌面 Chrome 的移动视口不代替这些结果。

HTML 预览先经加密通道读取资源，再在独立 opaque 沙箱显示；支持经典脚本、CSS 引用、图片及预览目录内的 `fetch`。当前安全预览不支持 ES 模块、Worker、XHR、嵌套 iframe 和表单提交，遇到这些资源会显示限制提示。真实浏览器已验证预览脚本无法直接访问业务 API。

验证包含真实浏览器密码登录、Service Worker 下的登录、邀请接收及活动流撤销，真实 Noise/WebSocket 的直连和中继、100 MiB 上传，以及 Web/Server/Desktop 构建。macOS 签名安装包、真机 iOS 前后台和 Mac 休眠尚未在对应设备验收；普通 PWA 的代码来源限制不会因这些功能上线而消失。

## macOS 自动中继

需要 Mac 在应用运行期间承担中继时，将上述 CLI 配置显式保存为 `~/.termdock/federation/relay.json`，设置 `chmod 600` 后重新打开 Termdock。Mac 主进程使用同一 Runtime CLI 启动中继，日志保存在同目录 `relay.log`；关闭单个窗口不影响它，退出应用会发送 SIGTERM 停止中继。网络重连由 CLI 负责。

此文件不存在时不会启动中继，也不会从已保存的 Mac 服务连接自动复制凭据或共享权限。修改配置后重启应用；移除配置后重启即可禁用。Mac 和 Runtime 都需升级到包含该 CLI 能力的版本。

## 入口服务直接访问目标

B 能直接访问 C 时，可在 B 的 `~/.termdock/federation/routes.json` 增加固定的 `directTargets`，无需运行 A：

```json
{
  "relays": [],
  "directTargets": [
    { "serviceId": "C-verified-service-identity", "url": "https://c.example", "caPath": "c-trusted-ca.pem" }
  ]
}
```

`caPath` 按入口配置目录解析。仅接受 HTTPS/WSS 服务地址或精确的 `/api/federation/secure` 路径；不接受客户端提供的任意目标 URL。实际访问路径为手机 → B → C，目标 C 仍独立验证手机身份和权限，B 只转发端到端密文。服务先以真实 TLS + 固定 Noise 身份验证登记地址，成功后才发布正向中转候选；后台每三十秒重新验证，失败后撤回并每五秒重试。检查失败不会移除其他独立反向提供者。配置已登记不代表当前在线，已打开的通道断线仍立即报错。

手机访问 B、希望连接家中 A 时，应在 **A 的后台配置 B 的固定目标**，由 A 主动向 B 登记 A 的反向通道；B 的中转列表应出现 A。不要把“A 的服务 ID + B 的 URL”写成 B 的直接目标：这只是一条身份与地址不符的配置。新版列表会显示验证中、身份不一致或连接失败的原因，不能连接未经验证的条目；名称相同时可用展示的服务 ID 尾部区分。只有反向通道、没有 A 的直连地址时，保存入口 B 与目标 A 的独立身份，不把 B 的地址当成 A 的直连地址。

修改 `directTargets` 后重启入口服务。客户端以稳定服务身份隔离标签页、文件状态和终端缓存；第一次验证本入口的直接服务时迁移升级前的标签页状态。工作组仍保留旧 origin 标识，并用已验证服务目录映射；工作组完成服务身份登记后，由服务后台通过加密通道直接投递；首次登记可通过 CLI 或新版已授权客户端完成，详见 `docs/collaboration.md`；磁盘静态加密不在此次传输改造范围内。

## 保留多个服务工作区

PWA 左侧栏提供服务切换器；macOS 原生客户端不显示这套切换栏，继续使用独立服务窗口和原生窗口切换。已固定身份的同一服务使用备用地址时优先复用现有窗口，不迁移或清除原存储分区。PWA 保留入口文档，并通过同源 `/workspace.html?termdock-workspace=<peerId>` 创建其他工作区，每个工作区拥有独立的 JavaScript 上下文、加密客户端和按服务身份划分的状态。常规切换不再整页刷新；首次授权时仍可能需要一次刷新来建立初始存储归属。

工作区地址只包含已保存的服务身份，目标地址和路线从本机服务目录读取；不加载目标服务的远程 HTML，不传递原生凭据，也不共享各服务的业务请求客户端。Service Worker 仅将这个固定应用入口识别为额外的业务请求所有者，预览文档仍受原有目标身份和预览路径约束。下载、通知跳转和手机键盘尺寸也按工作区处理。后台工作区暂停终端画面订阅，远端终端继续运行；系统回收整个 PWA 后，仍需恢复连接和缓存内容。

连接优先采用最近十分钟内成功的路线，慢路线在 400ms 后允许另一条已登记路线参与连接，最多同时两条；一次性配对保持串行，已验证的授权拒绝会停止当前连接尝试。前台恢复不再按后台停留时长直接断开连接，先进行有超时的权限检查，失败后快速重试并逐步退避。自动重连不能重新添加用户在其他工作区移除的服务。

## 多入口与多个中转提供者

同一目标可以由多个已获登记权限的中转同时提供，也可以同时保留入口直达目标的固定配置。各提供者分别续期和撤回，单个提供者退出不会移除其他提供者。新通道跳过已满载、过期、离线或已撤销登记权限的提供者；目标拒绝建连、超时或提供者断开时，只在通道尚未打开的阶段尝试下一个提供者。近期失败的提供者在五秒内降低优先级，但仍可作为最后候选重试。

默认单个提供者建连预算十秒，整轮提供者选择预算十五秒；前台、后台通知与服务间协作的中转连接预算统一为二十秒，给目标身份握手留出时间。通道打开后断线由调用端重新连接、重新验证目标身份，不在提供者之间重放已发送的密文或终端输入。旧尝试的迟到消息与取消后才完成的目标连接会被清理。

客户端保留同一入口身份的不同地址，仅对“入口身份 + 规范化地址”完全相同的记录去重，最多保留四个备用连接。每条入口地址仍分别申请短期路由票据；入口路由权限不替代最终目标的设备授权。

这里的多个中转指显式登记的候选路线，以及手机 → 入口 → 中转进程 → 目标的已有链路。系统不会从服务目录推导任意多级串联的可达性，也不会自动借用其他服务的路由授权。

自动验证覆盖中转失败切换、撤回、超时、满载、取消与迟到连接，包含真实 WebSocket 与 WSS + Noise 链路，以及上传下载、预览、后台通知和旧客户端桥接回归。真实 macOS/iOS 的工作区切换、前后台恢复、输入、上传下载、预览和通知路径仍待实机验收。


## 网络变化后的反向访问

A 配有 B 的固定直连目标时（包括桌面服务目录与管理员 routes.json），A 的后台服务会向 B 证明自身身份并登记仅通往 A 的反向通道。通道由 A 主动拨出，不要求 B 能主动连接 A 的公网地址；浏览器或桌面窗口关闭后，服务仍可维持它。两端都必须保持服务运行，A 到 B 的网络和 TLS 信任也必须有效。

后台同时读取同一系统用户的 Electron 目录 `~/.termdock/desktop.json` 和 Rust Preview 原生连接目录（macOS 为 `~/Library/Application Support/com.jovines.termdock.preview/connections.json`）。只安装 Preview 时也可自动登记：须先在 Preview 中连接并固定本机 A 和远端 B 的服务身份。目录变化约两秒内生效；移除 B、移除本机身份或更改证书信任会撤回或重建对应反向通道。两种客户端的配置各自独立，不复制密码、浏览器设备身份或授权；同一服务的不同地址分别保留，相同服务和地址的记录优先采用 Preview 的信任，管理员固定路由仍优先。

Preview 的 `certificatePins` 固定服务器叶证书，Electron 的目录固定 CA，两者独立验证。后台只在 TLS 检查阶段读取并核对 Preview 已批准的叶证书，随后 WSS 仍校验精确指纹、主机名与有效期；不会把叶证书指纹当作 CA 指纹，也不会在校验失败时改走未验证的连接。此修复随 **Node CLI/后台服务** 更新，仅更新 Preview App 不会替换已运行的旧后台。

访问已保存的 A 失败时，客户端可以检查其他已保存、固定身份的服务 B，确认 B 目录中实际存在且可用的 A，再尝试通过 B 回到 A。B 已授予当前设备路由权限时直接复用；若当前设备有 B 的管理权限且从未撤销该路线，可以仅为当前设备建立路由授权。无管理权限、通道不可用或存在撤销记录时不会自动授权。A 仍独立验证设备访问权限，B 的管理权限不授予任何 A 的终端权限。成功后保存 B 为 A 的备用入口，后续重连和后台通知可复用。

自动验证包含无桌面配置与仅有 Preview 配置时 A 主动登记到 B 的真实 WSS + Noise 通道、B 的列表发现、终端输入、文件校验、下载取消、后台通知接口，以及断线恢复、移除连接和证书信任变化。相关后台中转集成测试已在 Linux 和隔离的 macOS 临时环境运行；macOS 测试不替换已安装 App 或重启用户服务。签名 Preview GUI、真实 iOS 前后台与换网仍待对应设备验收。
