# 拖动生命周期

排序、调整尺寸、画布平移分别保留自己的位移算法。所有这些操作共用
`dragLifetime.ts` 的结束条件，避免各组件重复处理鼠标松开丢失。

- 排序列表统一使用 `components/DragDropContext.tsx`，不要直接引入库的
  `DragDropContext`。封装会自动启用中断 sensor，包含待抬起和已抬起状态。
- React 自定义拖动使用 `useDragLifetime(onFinish)`。确认本次按下可以开始拖动后，
  **先**调用返回的跟踪函数，**再**写入本次的拖动 ref；新开始会先结束旧操作。
- 多指画布使用 `useDragLifetime(onFinish, true)`。回调提供结束的 pointerId，
  只清理该指针；正常松手已处理的指针不应再次影响剩余手指。
- 非 React 或旧 mouse 入口使用 `observeDragLifetime`，保存其返回的 disposer，
  在宿主销毁时调用。它不负责业务位移或持久化。

全局事件只注册一套，运行时只有活动拖动订阅事件。捕获阶段先检查按键，确保
未按下的 mouse/pen move 不会先被库或组件执行。触摸事件不以 buttons 判断结束。
同时处理 pointercancel、丢失捕获、窗口失焦、页面隐藏、Escape 和卸载。

React 入口设置 `deferRelease`：正常 pointerup 先执行组件的保存/放置逻辑，
在本次事件结束后兜底清理。异常中断同步清理，组件不应借此执行点击、跳转或面板重排。
尺寸调整可以保留最后一次有效尺寸，排序取消则不提交目标，具体规则由调用者决定。
回调须可重复调用后不产生额外业务操作，并清除动画帧、计时器和手势锁。

`GestureManager` 仍负责终端触屏的手势优先级、争用与多指分派；远程桌面/手机输入
还需要发送对应协议的释放消息。这些规则不能由界面拖动层推断或代替。

回归覆盖：丢失松手后的无按键移动、待抬起状态、窗口失焦、隐藏、取消、捕获丢失、
多指隔离、触摸 buttons=0、键盘排序、正常完成顺序和卸载清理。
